# AI 助手多会话设计

## 目标

支持在 AI 助手中管理多个独立会话；每个会话记住自己的模型选择，每条 AI 回复保留生成时的供应商与模型信息。

## 交互

- 助手顶部增加会话入口和新建按钮。会话列表展示标题，支持切换、重命名、删除，按最近活动排序。新会话默认标题为「新会话」，首次发送后以首条指令自动命名，手动改名后不覆盖。
- 保留顶部模型选择器；切换模型仅影响当前会话后续请求。
- 新会话继承当前会话的模型选择作为初始值，此后各自独立。
- 原「清空对话」仅清空当前会话消息；删除会话需确认，删除最后一个会话后建立空会话。
- 生成期间可以切换或新建会话，原请求继续生成并写回发起会话。停止生成仅作用于当前会话；删除正在生成的会话时，确认后取消它的请求。每个会话最多一个生成任务。
- 回复头部显示「AI 助手  供应商名 · 模型 ID」，采用截图中的主次文字层级。流式生成时也显示该信息；思考过程、耗时、Token 信息保留。

## 数据边界

- 会话独立：消息、聊天上下文、输入草稿、待发附件、输入历史、选中的供应商与模型、生成状态、Token 统计。
- 供应商连接配置和 API Key 继续共用现有配置系统，不复制到会话记录。会话只保存供应商 ID 和模型 ID。
- 主编辑器文章仍是现有共享文档，各会话发送时捕获当时正文；应用 AI 修改稿沿用现有冲突确认。多会话功能不创建多个编辑器文档。
- 每条 assistant 消息保存生成时的 providerId、providerName、modelId 快照；修改供应商名称、删除供应商或切换模型不会改写历史标识。
- 如果会话选中的供应商/模型被删除或禁用，显示不可用提示并要求重新选择，不静默替换。其他会话的选择不受影响。

## 持久化与迁移

- 会话保存在当前浏览器 localStorage，刷新恢复会话列表、当前会话、消息、文字草稿、输入历史及模型选择；不新增云端聊天同步。
- 沿用现有附件隐私规则：图片和附件正文只保存在当前页面内存，刷新后不恢复；已发送文本附件保留名称与大小。
- 首次加载将旧单会话消息、输入历史和全局模型选择迁入「历史会话」。只有新结构成功保存后才记录迁移完成，避免迁移失败造成丢失或反复复制。
- 旧回复没有可靠模型来源，显示普通「AI 助手」，不将当前模型伪装成历史来源。
- 刷新后未完成回复标识为生成中断，支持继续发送；不会将残留生成状态恢复为无限加载。
- 保留当前每会话最近 20 条消息的落盘策略；存储失败时提示用户，避免静默清空其他会话。运行中的请求按会话 ID 和回复 ID 更新，不能通过当前选中会话定位。

## 实现边界

- 新增会话数据模块负责结构校验、迁移、持久化和会话操作。
- AiChatPanel 管理会话入口、当前视图及按会话归属的生成任务；异步附件读取也需绑定发起会话，避免切换后写错草稿。
- AiMessageBubble 消费回复来源快照，渲染供应商与模型信息。
- 不改现有后端协议；每次请求仍只发送所属会话的消息和所选模型。

## 验收

1. A/B 会话分别使用不同模型，切换和刷新后保持各自选择；输入历史、草稿、消息、统计互不串用。
2. A 生成时切换到 B 并发送，两个流式结果分别写回所属会话；停止/删除其中一个不影响另一个。
3. 每条回复在生成中和完成后均显示实际供应商与模型，切换模型或修改供应商名称不改变旧回复。
4. 旧记录迁移不丢失、不重复；缺失来源不猜测；不可用模型明确提示。
5. 覆盖存储异常、延迟返回、附件异步读取、删除会话、编辑重发等隔离回归测试。
6. 桌面抽屉/侧栏与移动端布局可用；完成相关测试、类型检查、构建和真实浏览器验证。

## 方案选择

推荐：浏览器本地多会话，共用供应商配置，按会话隔离生成任务。直接满足当前需求并兼容现有数据。

备选：切换会话前必须停止生成，实现较简单但会打断操作；或增加云端会话同步，需要额外存储、权限与同步冲突设计，本次不纳入。
