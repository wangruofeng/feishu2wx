# Markdown 原文查找替换设计

## 目标

在左侧 Markdown 原文编辑器中增加查找替换功能，支持普通文本、区分大小写和正则表达式匹配。用户可以浏览匹配项、替换当前项或替换整篇文档中的全部匹配项，并在编辑区直接看到全部匹配和当前匹配的高亮。

## 范围

首版包含：

- 工具栏下方的双行查找替换栏；
- 普通文本匹配；
- “区分大小写”和“正则表达式”开关；
- 上一个、下一个和循环导航；
- 全部匹配背景高亮和当前匹配强调；
- 替换当前项和整篇文档全部替换；
- 正则替换文本中的 `$1` 等捕获组引用；
- 键盘快捷键和无障碍标签；
- 与现有撤销、语法高亮和滚动行为集成。

不包含：

- 仅在选区内查找或替换；
- 保存查找历史或跨会话保留设置；
- 整词匹配开关；
- 替换前逐项确认；
- 更换现有 textarea 编辑器实现。

## 界面与交互

查找栏位于格式工具栏和编辑区之间，采用双行布局：

1. 第一行包含查找输入框、匹配计数、上一个、下一个、区分大小写、正则表达式和关闭按钮。
2. 第二行包含替换输入框、“替换”和“全部替换”按钮。

`Cmd/Ctrl+F` 打开查找栏并聚焦查找输入框；如果已有编辑器选区，则用选中文本预填查找词。Enter 跳到下一个匹配，Shift+Enter 跳到上一个匹配。Esc 关闭查找栏，将焦点归还编辑器，但不修改文档。

空查询显示 `0/0`，不产生匹配。无匹配时显示 `0/0` 并禁用替换按钮。非法正则在查找栏内显示简短错误，显示 `0/0` 并禁用导航与替换。

查找栏在移动端保持两行结构，单行内部允许水平滚动或按现有断点紧凑排列，不覆盖 Markdown 内容。

## 匹配语义

普通文本模式会转义正则元字符，再根据“区分大小写”开关使用或省略 `i` 标志。正则模式直接编译用户输入，并始终使用全局匹配；关闭“区分大小写”时附加 `i` 标志。

匹配计算输出按文档顺序排列的字符范围，每项至少包含 `start`、`end` 和替换当前项所需的捕获组信息。范围索引与 textarea 一致，使用 JavaScript UTF-16 代码单元。为避免零长度正则导致死循环，每次零长度匹配后至少前进一个完整 Unicode 码点对应的代码单元数；零长度匹配可以导航，但“替换当前项”和“全部替换”必须保持有限、确定的执行次数。

查询或匹配模式变化后重新计算匹配项。当前项优先选择 textarea 光标位置之后的第一个匹配；若光标之后没有结果，则循环到第一项。文档因输入或替换发生变化时，重新计算并尽量保持当前位置附近的结果。

## 高亮架构

保留现有 textarea 和 Markdown 语法高亮层，在两者之间增加独立的查找高亮层：

```text
textarea（透明文字、caret、原生选区与输入）
查找高亮层（全部匹配背景、当前项强调）
Markdown 语法高亮层（现有 token 文字颜色）
```

查找高亮层按字符范围生成转义后的文本和标记元素，不解析 Markdown 语法。它与 textarea 使用完全相同的字体度量、padding、换行规则和宽度，并与语法高亮层一起响应 textarea 的横向、纵向滚动。高亮层设置 `pointer-events: none`，不会影响输入、拖拽或选区操作。

导航到匹配项时，通过 textarea 的 `setSelectionRange()` 选择对应原文，并将该范围滚动到可见区域。当前项同时使用更强的背景或描边 token，与普通匹配区分；亮色和暗色主题都使用项目设计 token 或主题覆盖值。

## 状态与修改流程

查找栏状态保存在 `EditorPane` 内，包括是否打开、查找词、替换词、匹配模式、匹配列表、当前匹配序号和正则错误。状态不写入 localStorage，也不提升到 `App`。

“替换”只修改当前匹配。修改前调用现有 `pushHistory()`，更新 Markdown 后定位到替换内容之后的下一项。“全部替换”作用于整篇 Markdown 原文，在一次操作中生成完整新文本，只调用一次 `pushHistory()` 和一次 `setMarkdown()`，因此一次撤销即可还原。

正则模式下，替换文本遵循 JavaScript `String.prototype.replace` 的替换语义，支持 `$&`、`$1` 等引用。普通文本模式下，替换文本按字面值插入，`$` 不具有特殊含义。

## 错误与边界处理

- 空查找词不编译表达式。
- 非法正则被捕获并转成栏内状态，不抛到 React 渲染链路。
- 零长度正则不会造成匹配或替换死循环。
- 匹配文本可跨行；高亮层继续使用 `pre-wrap` 显示。
- 查找栏关闭后清除可见高亮，但保留本次查找和替换输入，重新打开时可继续；组件卸载后自然清空。
- 当格式快捷键、粘贴、拖拽、导入、历史恢复或 AI 修改稿改变原文时，匹配结果从最新 Markdown 重新计算。

## 可测试性

将纯匹配和替换逻辑放在独立工具模块中，DOM 行为留在 `EditorPane`。单元测试覆盖：

- 普通文本的大小写敏感与不敏感匹配；
- 正则匹配、跨行匹配和捕获组替换；
- `$` 在普通文本替换中按字面处理；
- 非法正则和零长度正则；
- 替换当前项与全部替换的结果。

组件测试覆盖：

- `Cmd/Ctrl+F` 打开并聚焦，Esc 关闭并归还焦点；
- Enter 和 Shift+Enter 循环导航；
- 匹配计数、按钮禁用状态和错误提示；
- 匹配高亮与当前项高亮；
- 单次替换和全部替换只各产生一个可撤销操作；
- 查找高亮层与 textarea 滚动同步。
