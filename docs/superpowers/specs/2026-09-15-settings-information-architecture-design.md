# 配置页信息架构重组设计

## 背景

当前配置面板以单列长列表呈现，十个分组同时展开。“通用”同时包含编辑器行为、AI 面板、界面明暗和文章主题色；文章主题的选择与“主题管理”又相距较远。随着保存主题、配置迁移和公众号推送等能力增加，用户需要依靠滚动和记忆寻找选项，也不容易判断“主题”“界面主题”和“完整配置”的差异。

本次仅重组配置页的信息架构、文案和响应式导航，不改变配置值、持久化键、导入导出格式或业务行为。

## 目标

- 让用户按照“设置文章外观 → 调整排版 → 设置内容组件 → 调整编辑体验 → 发布或迁移”的任务路径找到配置。
- 桌面端减少纵向滚动，手机端保持完整可达且不挤压内容。
- 将文章主题、界面明暗和完整配置三个概念明确区分。
- 保持所有现有功能和数据兼容。

## 非目标

- 不增加、删除或改变任何配置项。
- 不改变 localStorage 键、主题 JSON 或完整配置 JSON 的结构。
- 不改动预览、复制、导出、CLI 或公众号推送的渲染行为。
- 不重做设置控件的基础视觉体系。

## 信息架构

配置页重组为五个一级分类。

### 1. 主题与外观

- 自定义主题色
- 字体
- 主题管理：保存当前配置、应用、导入、导出和删除主题

该分类负责文章最终呈现的整体视觉。主题管理紧邻主题色和字体，帮助用户理解保存主题会捕获哪些文章排版配置。

### 2. 文章排版

- 标题：H1/H2 的底线、反色和对齐
- 正文：文本对齐、分割线、荧光笔颜色
- 文章结构：显示元数据、文章首部片段、文章尾部片段

该分类负责文章级结构与连续正文的排版。首尾模板属于文章结构，而不是系统模板管理。

### 3. 内容样式

- 引用块：背景、边框色、间距
- 图片：样式、圆角
- 表格：阴影
- 代码块：极简或现代

该分类集中管理 Markdown 内容组件的局部样式。

### 4. 编辑体验

- 智能粘贴转换
- Markdown 源码配色
- AI 面板显示方式
- 界面明暗（由原“主题模式”改名）

该分类主要影响应用操作和编辑界面；例外是「Markdown 源码配色」——它同时驱动预览与复制/导出内容的代码块配色（`src/utils/codeHighlightThemes.ts`），属于跨编辑与输出的联动配置。

### 5. 发布与数据

- 微信公众号链接自动适配
- 草稿箱推送配置
- 完整配置导入和导出（由原“配置迁移”改名）

该分类覆盖文章离开编辑器后的发布行为，以及用户级配置迁移。主题导入导出继续留在“主题与外观”，并通过说明文案与完整配置 JSON 明确区分。

## 响应式交互

### 桌面端

- 配置面板从应用右侧展开，并为顶栏和主工作区预留同宽空间；面板顶部通过横向 Tab 切换五个分类。
- 分类标签栏高度与顶栏一致（桌面 `--top-bar-height`、手机 `--top-bar-height-mobile`），侧栏展开时标签栏与顶栏在视觉上连成一排。
- 分类名只出现在标签上，内容区顶部不再重复显示大标题；面板通过 `aria-labelledby` 关联当前标签获得可访问名称。
- Tab 使用文字和简洁图标辅助识别，空间不足时可横向滚动。
- Tab 下方只渲染或显示当前分类，分类内部继续沿用现有分组标题和控件；选择、下拉等控件随侧栏内容区收窄，不再在较宽的浮层中横向撑满。
- 面板打开后默认进入“主题与外观”。在同一次面板打开期间切换分类时保留当前分类；关闭后重新打开则回到默认分类。

### 手机端

- 保持与桌面端相同的内容区顶部横向标签栏。
- 标签可横向滚动，不压缩文字或省略分类名称。
- 当前分类标签应自动保持在可视区域内。
- 内容使用单列布局，所有操作均无需悬停即可完成。

响应式断点沿用项目既有移动端规则，避免引入第二套不一致的断点。

## 状态与行为

- 当前分类是配置面板内部的临时 UI 状态，不写入 localStorage。
- 切换分类不会关闭面板，也不会重置输入框、状态提示或未保存的组件状态。
- 微信配置对话框继续由配置面板管理；打开和关闭对话框不改变当前分类。
- 点击面板外部仍关闭配置面板，保持现有行为。
- 隐藏的文件输入继续与对应按钮关联，导入流程不变。

## 无障碍

- 顶部导航使用明确的 tablist、tab、tabpanel 语义。
- 当前分类通过 `aria-selected` 和可见选中态同时表达。
- 分类可通过键盘方向键切换，Tab 键进入当前面板内的控件。
- 每个标签与唯一内容面板通过 `aria-controls`、`aria-labelledby` 关联。
- 焦点样式沿用现有 token，不只依赖颜色表示选中状态。

## 组件结构

- 在 `SettingsPanel` 内定义稳定的分类标识与展示顺序，避免从标题文字反推分类。
- 使用一个共享分类导航数据源生成顶部 Tab。
- 将现有 JSX 按五个分类重新包裹；不为了此次重组拆分业务状态或回调。
- 样式继续维护在 `SettingsPanel.css`，颜色、间距和圆角使用项目 token。
- 分组分隔线只绘制在相邻可见分组之间（`border-top` + 兄弟选择器），切换分类后末尾不会显示多余横线。

## 测试与验收

- 单元测试覆盖五个分类名称、默认分类和切换后内容可见性。
- 验证旧配置项均且仅出现于一个新分类中。
- 验证主题保存、应用、导入、导出、删除仍可操作。
- 验证完整配置导入导出与公众号配置入口仍可操作。
- 验证桌面和手机顶部标签在既有响应式断点下均可完整访问。
- 浏览器检查浅色、深色主题及窄屏宽度，确认无横向页面溢出、遮挡或不可达操作。
- 运行项目现有测试与构建；已知基线警告单独报告，不与本次回归混淆。
